## 작업 순서와 검증

1. 해설 생성·정제 규칙 수정 후 내부 ID 노출 검사와 타입 검사를 수행한다.
2. 용신 로직을 9장 명세의 조후·억부·대표 글자 규칙과 대조하고 대표 사례를 계산한다.
3. 신강 지수와 모바일 컨테이너를 수정한 뒤 작은 뷰포트에서 가로 넘침을 확인한다.
4. 대운별 세운 생성 및 선택 UI를 구현하고 각 대운의 10개 연도 범위를 검사한다.
5. 오행 차트를 수정하고 다섯 오행의 라벨·색상·수치 표시를 확인한다.
6. TypeScript, 정적 Next.js 빌드, Toss 빌드를 수행한다.

## 용신 감사 결과

### 명세와 일치하는 부분

- 조후 붕괴 조건은 화, 수 중 한쪽만 20% 이상인 경우와 양쪽이 존재하면서 강한 쪽이 20% 이상이고 약한 쪽이 1/3 이하이거나 절대 차이가 20%p 이상인 경우를 구현한다.
- 조열이면 수(水), 한랭이면 화(火)를 조후용신으로 선택한다.
- 조후가 중화이면 SI 0 이상에서 식상, 재성, 관성, SI 0 미만에서 인성, 비겁을 기본 후보로 삼고 과도한 기운을 제압하거나 설기하는 후보를 우선한다.
- 대표 글자는 일간을 제외한 표면 7글자를 먼저 비교하고, 표면에 용신 오행이 없을 때만 지장간을 확인한다.
- 용신 글자가 없으면 용신을 생하는 희신 글자를 찾는다.

### 이번에 수정한 오류와 누락

- 희신 글자를 대신 선택한 경우에도 용신 대표 글자라고 표시하던 문구를 `희신 보완 기준`으로 바로잡았다.
- 용신과 희신 글자가 모두 없을 때 막연히 대운에서 보완된다고 표시하던 문구를 실제 최초 용신 유입 대운의 나이와 간지에 연결했다.
- 모든 용신 오행과 대표 글자 한자에 한글 독음을 병기했다.
- 화와 수의 절대 기도비율 차이가 20%p 이상인 경우를 조후 불균형 조건에 추가했다.
- 억부용신 선택에서 과도한 식상, 재성, 관성을 먼저 조절하는 인성 또는 비겁을 우선하도록 보완했다.
- 일간을 제외한 표면 7글자를 지장간보다 먼저 비교하고 대표 글자에 해(亥), 묘(卯) 같은 지지를 반환할 수 있도록 수정했다.
- `갑을병병 / 신해신오`, `기을병병 / 묘해신오` 사례가 모두 수 용신, 일지 해(亥)를 반환하는 회귀 테스트를 추가했다.
- 결과 카드의 임의 환산 백분율을 제거하고 실제 점수 소계와 최종 점수를 표시했다.
- `아이의 기질 요약`을 오행 균형, 가점, 감점, 아이 기질을 포함한 `택일에 관한 총평`으로 확장했다.
- Detail Report가 열려 있을 때 휴대폰 뒤로가기가 결과 화면을 이탈하지 않고 다이얼로그만 닫도록 히스토리를 연동했다.

### 남은 개선사항

- 현재 용신은 산출·해설·대운 분석에는 사용하지만 최종 후보 점수에는 직접 가감되지 않는다. `calculateBaseScoring()`도 용신 인자를 아직 사용하지 않는다. 용신·희신 대운 가감점은 별도 가중치 명세를 확정한 뒤 연결해야 한다.
- 현재 조후 판정은 제공된 9장 명세대로 화·수 기도비율만 사용한다. 향후 월령·투간·통근까지 확장하려면 판정 기준을 먼저 문서화해야 한다.

- `scripts/verify-yongshin.ts`: 조후 절대 차이, 억부 우선선택, 표면 대표 글자와 문서 사례 검증.
- 자동 검증 스크립트 통과.
- TypeScript `npx tsc --noEmit` 통과.
- Next.js 정적 빌드 통과.
- Toss `birthdaygift.ait` 빌드 통과.
