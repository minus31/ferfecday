# 출시 연결 체크리스트

코드 구현과 실제 외부 서비스 개통을 구분합니다. 설정하지 않은 서비스를 연결 완료로 간주하지 않습니다.

## 로컬 테스트 계정

Supabase 연결 전 화면을 검수하려면 로컬 `.env.local`에 `NEXT_PUBLIC_LOCAL_TEST_ACCOUNT=true`를 설정합니다. 기존 로그인 화면에서 `brith@day.com` / `1234`를 입력하면 로그인되며, 세션과 검색은 브라우저 `localStorage`에만 최대 20건 보관됩니다. 테스트 계정에는 전체 해설 권한이 적용됩니다. Supabase, 보호 API, OpenAI 이미지, 실제 결제는 호출하지 않습니다. 환경 변수를 바꾼 뒤 개발 서버를 다시 시작해야 합니다.

이 로컬 계정은 인증, 계정 간 격리, 서버 저장, 이메일, 실제 AI 생성 검증을 대체하지 않습니다. `npm run check:launch`는 로컬 테스트 계정이 켜져 있으면 실패합니다. 공개 배포 전 값을 반드시 `false`로 바꾸고 실환경 검증을 완료합니다. 운영용 Supabase 테스트 계정 절차는 아래 2절처럼 별도로 검증합니다.

## 1. 전용 Supabase

- 사용자 지정 조직에 `birthdaygift` 전용 프로젝트를 생성합니다. 기존 타 서비스 프로젝트는 사용하지 않습니다. 권장 저장 지역은 서울이며, 실제 프로젝트 선택에 맞춰 방침의 국가와 위탁 조건을 확정합니다.
- `supabase/migrations/202609170001_product.sql`을 SQL Editor 또는 Supabase CLI로 적용합니다. 새로운 전용 프로젝트를 위한 초기 마이그레이션이며 기존 테이블을 삭제하지 않습니다.
- `.env.example`의 Supabase URL과 공개 anon/publishable 키를 빌드 환경에, service_role 키는 Vercel 서버 환경에만 설정합니다.
- 이메일 가입, 이메일 확인을 활성화하고 비밀번호 최소 길이를 8자 이상으로 설정합니다. SMTP 발신 도메인, 템플릿, 발송 한도, 스팸 폴더 도착 여부를 검증합니다.
- Auth Site URL은 실제 웹 도메인, redirect allow list에는 웹과 토스의 `/account` 경로를 정확히 등록합니다. PKCE는 확인 링크를 가입한 브라우저에서 여는 것이 기본입니다. 다른 기기에서 확인했다면 원래 화면으로 돌아와 로그인합니다.
- 액세스 토큰은 짧게, 권장 15분, 갱신 토큰 회전과 재사용 탐지를 켭니다. 서버는 JWT 검증뿐 아니라 `auth.sessions` 존재와 생성 후 30일 이내 조건을 매번 검사합니다. 로그아웃된 세션과 만료된 세션은 거절합니다.
- 저장 데이터 테이블은 anon/authenticated 직접 읽기, 쓰기가 금지되어야 합니다. `service_role`만 접근합니다. 공용 삽화 버킷은 공개 읽기, 업로드는 서버 전용입니다.
- 실제 두 계정으로 다른 계정의 검색 ID 접근이 404인지, 갱신 후 재조회가 되는지, 로그아웃 이전 토큰이 401인지, 탈퇴 후 기록이 삭제되는지 확인합니다.

## 2. 테스트 계정

서버가 공개 비밀번호 `1234`를 검사한 뒤 비공개 강한 비밀번호로 Supabase에 인증합니다. 이메일 문자열이나 사용자가 수정할 수 있는 user_metadata만으로 열람권을 주지 않습니다.

1. 보안 난수 도구로 24자 이상 임의의 `TEST_ACCOUNT_PASSWORD`를 생성해 로컬과 서버의 비밀 설정에 저장합니다. 비밀 값은 출력하거나 커밋하지 않습니다.
2. `npm run setup:test-account`로 `brith@day.com`을 생성합니다. 기존 일반 계정이라면 자동으로 관리자 권한을 부여하지 않고 중단합니다.
3. 서버에 `TEST_ACCOUNT_ENABLED=true`를 설정합니다. 사용자는 `brith@day.com` / `1234`로 로그인하며 결제 없이 모든 해설을 봅니다.
4. 이 계정은 공개된 공용 테스트 계정입니다. 실제 개인 정보나 가족 기록을 입력하지 않습니다. 공개 출시 시 비활성화를 권장합니다. 비활성화하면 기존 세션도 더 이상 결제 예외를 받지 않습니다.

## 3. Vercel과 OpenAI

- 서버에 `OPENAI_API_KEY`, 필요 시 `OPENAI_SAJU_MODEL`, `OPENAI_IMAGE_MODEL`을 설정합니다. 해설은 키가 없으면 Vercel AI Gateway 인증으로도 연결할 수 있지만, 이미지 생성에는 직접 OpenAI 키가 필요합니다.
- 두 함수의 최대 실행시간은 300초입니다. 해설 요청은 260초, 이미지는 200초에 중단합니다. 모델 사용 권한, 결제 수단, 지출 한도, 실제 지연시간을 확인합니다.
- `NEXT_PUBLIC_SERVICE_API_URL`과 `ALLOWED_ORIGINS`에 실제 호스트를 설정합니다. 미리보기 도메인을 무조건 허용하지 않습니다.
- `npm run build`는 웹 정적 결과와 토스 아티팩트를 만듭니다. Vercel에는 `/api/service`가 실제 Function으로 배포되는지 확인합니다. `.env.local` 변경 뒤 정적 앱은 다시 빌드해야 합니다.
- 후보 하나의 보고서를 열어 OpenAI 요청이 한 번 발생하는지, 12장과 전체 대운이 함께 저장되는지, 다시 열 때 저장된 결과를 재사용하는지 확인합니다. 일주가 같은 두 후보의 이미지 URL도 동일해야 합니다.
- 해설 캐시는 `(검색, 후보, 버전)` 기준입니다. 키 미설정 또는 일시 실패로 저장된 기본 해설도 재사용합니다. 운영 시작 전에 시험 기록을 새로 만들거나 `REPORT_VERSION`을 올려 재생성 대상을 명확히 정합니다. 이미지 스타일을 바꿀 때는 `portrait-v1` 키 버전을 변경합니다.
- 원본 일주 자료 URL은 첫 장에 표시하지 않습니다. 일주 이미지의 얼굴은 실제 자녀의 외모 예측이 아니라 상징 창작물이며 AI 표시를 유지합니다.

## 4. 개인정보와 고지

- 사용자가 추후 제공하기로 한 운영자, 개인정보 보호책임자, 사업장과 사업자 정보를 공개 설정에 반영합니다.
- 실제 Supabase 저장 국가, 운영 지원 처리 국가, Vercel 배포와 로그 지역, 제공자 연락처, 백업 삭제 주기, 로그 보유기간을 계약과 대시보드로 확인해 `/privacy`의 준비 문구를 확정합니다.
- AI 해설에 이메일과 계정 정보는 보내지 않습니다. 다만 사주 구성과 시기 정보도 재식별 가능성을 고려해 국외이전 안내에 포함했습니다. AI 사전 고지, 해설과 이미지의 AI 표시를 유지합니다.
- 별도 체크박스로 서비스 약관과 개인정보 수집, 국외이전을 확인합니다. 동의 기록에는 정책 버전과 시점이 저장됩니다. 정책의 핵심 처리 조건이 바뀌면 버전을 올리고 재동의를 받아야 합니다.
- 카메라, 연락처, 사진, 기기 위치 권한은 요청하지 않습니다. 마케팅 동의는 수집하지 않습니다.
- 지원 메일은 `rouf____@naver.com`입니다. 복구 요청은 본인 확인 후 Supabase의 공식 비밀번호 복구 절차로 처리하며 이메일로 비밀번호를 받거나 평문 비밀번호를 전달하지 않습니다.
- 정책 검토 후 `PRIVACY_REVIEW_COMPLETE=true`, `npm run check:launch`를 실행합니다. 설정 검사는 법률 적합성을 보증하지 않습니다. 실제 제공 방식과 계약에 대한 검토가 필요합니다.

확인한 공식 근거: [AI기본법](https://www.law.go.kr/LSW/lsInfoP.do?ancYnChk=&chrClsCd=010202&efYd=20260122&lsiSeq=282791&urlMode=lsInfoP)의 투명성 의무, [개인정보 보호법 국외이전](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029331979), [OpenAI API 데이터 처리](https://platform.openai.com/docs/guides/your-data), [Supabase 세션](https://supabase.com/docs/guides/auth/sessions), [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security). 사용자 제공 과태료 요약을 그대로 법률 보증으로 사용하지 않습니다.

## 5. 다음 세션: PG 실제 연결

현재 버튼은 Toss Payments용 주문을 준비하고 `not-configured`를 반환합니다. 브라우저에서 결제 성공을 흉내 내거나 열람권을 부여하는 엔드포인트는 없습니다.

- PG 계약과 채널 정책을 먼저 확인합니다. 토스 미니앱에서 외부 PG 사용이 허용되는지, 인앱 결제 정책이 별도로 적용되는지도 출시 채널의 최신 문서로 확인해야 합니다.
- `birthdaygift_orders`의 서버 생성 주문 ID, 서버 고정 3,900원, KRW를 사용합니다. 클라이언트의 금액과 `paid=true` 값을 신뢰하지 않습니다.
- 승인 API에서 PG 서버와 금액, 주문, 소유자를 검증한 뒤 트랜잭션으로 주문 상태와 검색 단위 `birthdaygift_entitlements`를 함께 기록합니다. 웹훅 서명, 중복 승인, 취소, 환불과 열람권 회수도 처리합니다.
- 판매자 필수 정보, 공급 시점, 청약철회와 디지털 콘텐츠 관련 고지, 환불 절차를 결제 전에 제공합니다.
- 승인, 환불 주문은 탈퇴 시 계정 연결만 끊고 보존하도록 테이블을 준비했습니다. 실제 판매 개시 전 법정 보유기간과 기간 만료 삭제 작업, 분쟁 보존 예외를 구현합니다. 미결제 주문과 검색, 보고서는 탈퇴 시 삭제됩니다.
- 서로 다른 두 검색, 같은 검색의 열 후보, 재로그인, 취소와 환불을 실제 PG 테스트 모드로 검증한 뒤 유료 판매를 켭니다.

## 검증 범위

`npm run verify`: 계산 회귀, Top10 다양성, 과거 날짜, 표시 시각, 60일주 해설 길이와 문구, 원진/귀문/공망, 인증/소유권/열람권, AI 요청과 캐시, SQL 권한과 세션 검증.

`npm run test:e2e`: 데스크톱과 모바일에서 가입, 과거 날짜 선택, 검색 저장, 새로고침, 유료 영역 미노출, 결제 미연동 안내, 전체 대운, 이전 결과 조회, 로그아웃, 테스트 계정. 인증과 저장은 테스트 대역이므로 실제 Supabase와 이메일 확인, AI 유료 호출의 운영 검증을 대체하지 않습니다.
